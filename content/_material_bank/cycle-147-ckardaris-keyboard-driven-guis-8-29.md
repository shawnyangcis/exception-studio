## 核心论点 (从博客正文提取)

### 1. TUI vs GUI 二分不重要
> "On one hand, I understand the GUI-positive arguments of the post author. ... On the other hand, as a heavy terminal user, I also greatly appreciate all TUIs that allow me to 'stay' in the terminal and fulfill all my needs."

### 2. Keyboard-driven 是 UX 完整性的 will 问题, 不是 feasibility 问题
> "While it's true that if you randomly pick a GUI and a TUI application, the latter is more probable to be fully keyboard-driven, this does not tip the scale in favor of developing TUIs over GUIs. What it does is highlight the inadequacies of keyboard navigation in many GUI applications. There is nothing preventing a GUI from being fully keyboard-driven — just like or even better than — a TUI."

### 3. GNOME HIG 引用 — 散文站哲学主轴「不分类不解释只管在」具体化
> "the GNOME Human Interface Guidelines state that just as it should be possible to perform every action with a pointing device, every action should also be possible with the keyboard and that it should be possible to move around and interact with every part of your user interface using the keyboard"

### 4. Solo engineer first GUI app "Klisi" 哲学实践
> "For my first ever GUI application, Klisi, I invested some time to implement keyboard shortcuts targeting the whole range of available actions."

### 5. 散文站哲学主轴「不分类不解释只管在」直接对应
> "Keyboard navigation is not that hard to achieve in most cases and results in an overall better user experience. It is not a matter of feasibility, but a matter of will on the application developer's part."

> "Do not compromise on the user experience you provide with your application. Strive to make it as intuitive as possible. To that end, enabling full keyboard navigation should not be ignored."
