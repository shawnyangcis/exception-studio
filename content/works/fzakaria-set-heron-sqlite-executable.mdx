## setheron 的核心论点

> "Your executable is, in fact, a relational database."

ELF 二进制文件结构：

- section header 是 schema
- relocation 是索引
- symbol table 是数据

Windows PE/COFF 也是。
.NET assembly 也是。
Go 编译产物也是。

区别只是没人写一个 `sqlite3` client 让你查 ELF。

SQLite 赢在哪？
它自带工具。

`sqlite3 foo.db`、`.schema`、`.dump`、PRAGMA——你不需要理解 B-tree / page cache / write-ahead log 才能跑 SELECT。

ELF 也自描述。
但你需要的工具散落了：objdump / readelf / gdb / nm / strings。

**表征决定工具。**

## 两组对照

### 数据库 vs 二进制

SQLite 文件：

- 自描述（schema 在 file 内部）
- 自带工具（sqlite3 CLI）
- 通用（任何语言有 binding）

ELF 文件：

- 自描述（section header）
- 工具散落（objdump / readelf / nm）
- 平台绑定（Linux only / Windows PE / Mac Mach-O）

表征换一下 = 工具集中到一个 sqlite3 CLI = 整个生态涌现。
