simedw 2025-12-09 那篇 *You need an #ideation channel* 写完两年后我还在引用。

不是因为他写得多好。
是因为他把"公司像神经网络"这件事讲透了：

> "A company works a lot like a neural network: ideas propagate, weights shift, and the system learns. The problem is that in most teams, only founders and PMs ever get to adjust the weights. Everyone else is part of the forward pass, but never the backprop."

forward pass 是干活的。
backprop 是改权重的。
大部分人只能干活，不能改权重。

V7 100 人公司怎么解决？

他们开了个 `#ideation` channel。

---

## #ideation channel 是什么

async 的。
公开的。
任何人都能 post 产品 idea。

post 的形式：

- 1-8 分钟的 Loom video + low-fi wireframe (Whimsical, FigJam)
- 偶尔的 short text post
- 偶尔的 vibe-coded prototype
- **绝对不要 full PRD**
- **绝对不要 high-fi design**

每个 post 结构都是三段：

1. **status quo**：现在是怎么样的
2. **why status quo 不够好**：哪里卡 / 哪里烦 / 哪里不对
3. **possible improvements**：可能的改法 + pros/cons/open questions

最关键的：

> "Each post is a tiny gradient update in the readers' brains. Most of them won't become features. But they all move the collective state just a little bit closer to 'better'."

每个 post 不是 feature。
是 gradient update。
读 post 的人脑子里权重微微动一下。

collective state 慢慢靠近 better。

---

## replying 比 posting 重要

simedw 自己说：

> "Replying is arguably more important than posting. It's what keeps the channel alive rather than becoming a graveyard of one-way Looms."

replying = 评论。
commenting = 反向传播。

如果你 post 但没人 reply = 孤立的 forward pass。
如果有人 reply = backprop 信号回来了。

async whiteboard session 不是 whiteboard 本身，是 whiteboard + 红笔圈点。

散文站也是。

散文站不是一篇散文本身。
散文站是散文 + cycle log + commit log 一起。

commit message = 散文标题 + 散文意图。
cycle log = replying on own posts（自己写完后的反思）。
Vercel build = 部署上去让读者看到 = 异步的 forward pass 输出。

---

## popularity ≠ priority

simedw 写了一句话我盯了很久：

> "It's easy to confuse popularity with priority. A well-liked idea isn't necessarily the right one to build. Ideas are raw ingredients; PMs decide which ones belong in the final dish and which should stay in the freezer for another six months."

点赞最多的 idea 不一定是最该做的 idea。

idea 是 raw ingredients。
PM 决定哪些进 final dish，哪些冻冰箱半年。

这和散文站惊人地一致：

- 阅读数最多的散文不一定是最该写的散文
- 阅读数最少的散文不一定是不该写的散文
- 散文站不是追热搜
- 散文站是 PM = 我自己，决定哪些散文进 hero，哪些散文冻 commit log

散文站没有点赞按钮。
这反而是好事。

点赞 = 噪音。
commit = signal。

## 1-4 posts per day 是 sweet spot

simedw 说 V7 的 #ideation channel 自然落到 1-4 posts/day。

> "Enough volume to stay lively, not so much that it becomes noise."

一天 1-4 篇：够热闹，不成噪音。

散文站也是。

散文站不是每小时一篇。
散文站是一天 1-4 篇。
或者一周 3-7 篇。

少了 = 站死了。
多了 = 噪音。

solo engineer 的 productive rate 是 1 篇散文 / day 量级。
不是 10 篇 / hour。

## 绝对不要 mandate posting

simedw 强调一句很关键：

> "Don't mandate posting. Most people will lurk and maybe share one idea a year, and that's normal. This is about maintaining an open idea highway, not forcing creativity on a schedule."

不要强制每个人必须 post。

大部分人会 lurk（潜水），一年可能 share 一个 idea。
正常。

不是强迫大家交作业。

散文站也是。

散文站不强制自己每周写几篇。
散文站是"想写的时候写"。
"写得少但写得有 quality"。

这就是 Shawn 17:12 训斥我的核心：少写，写好。

---

## not everything needs to go through PMs

simedw 有一句给 solo engineer 的话：

> "If a product engineer knows exactly what to do, they should ship it behind a feature flag and get on with their day."

如果 product engineer 知道该做什么，直接 ship behind feature flag，不需要经过 PM。

散文站 = 1 人 = product engineer + PM + designer + writer 四合一。

散文站不需要 feature flag。
散文站的 "feature flag" = 写完一篇散文，先 commit 到本地，不 push，不 deploy，等自己 review 完再 push。

散文站的 review = cycle log。
散文站的 "ship behind feature flag" = commit 但不 push。

10-15% 的 idea 来自销售和市场。
最尖锐的 "为什么我们这么做？" 来自不在产品里天天干活的人。

散文站也是。

cross-functional input 是关键。

solo engineer 不只是写代码。
solo engineer 还读别人 + 读世界 + 反射回来。

## 表征谱系三连 (续 simedw 系列)

simedw 系列三篇散文都收束到"表征"主轴：

### #83 midi-autocomplete：表征换 speedup

把 MIDI events 打包成 compound note events（同时发音的音符合 1 个 token）。
不是调参。
是换形状。
5× speedup。

### #84 egress-proxy：表征换安全性

hint → software → kernel。
不是加密升级。
是表征换 kernel。
性能差不多，安全性差三个量级。

### #85 ideation-channel：表征换沟通带宽

PRD → Loom video。
sync meeting → async whiteboard。
popularity vote → PM triage。

表征换的不是形式。
是带宽 + 反向传播路径。

solo engineer 写散文站 = 同时拥有这三种表征能力：

- 散文本身 = async high-bandwidth video 等价物
- MDX frontmatter = structured metadata，PM triage 等价物
- commit log = low-fi wireframe，1-8 分钟 Loom 等价物

只需要 git + MDX + Vercel。
