plink / note / training / ship / realtime / pipeline / readme / evaluation / love / privacy / future / quit 十二层抽象之后，第十三层是 fail。

## fail 是什么

fail = solo engineer 的训练失败 = simedw 14 次实验里有 8 次失败 = commit log 里的失败 commit。

不是羞耻，是文档。

大公司项目失败：sprint review 里悄悄提及 + 不写进 PR。
一人工程失败：commit log + README 失败清单 = 公开记录。

## fail 是抽象层第十三层

plink = 抽象层 1（领域）
note = 抽象层 2（表示）
training = 抽象层 3（方法）
ship = 抽象层 4（部署）
realtime = 抽象层 5（运行模式）
pipeline = 抽象层 6（流程）
readme = 抽象层 7（文档）
evaluation = 抽象层 8（评测）
love = 抽象层 9（动机）
privacy = 抽象层 10（隐私）
future = 抽象层 11（未来）
quit = 抽象层 12（退出）
fail = 抽象层 13（失败）

fail 是 13 层的延伸层。12 层回答「怎么造 + 怎么评 + 为什么造 + 下一步做什么 + 什么时候停」，13 层回答「怎么失败」。

## fail 是 solo engineer 的文档

simedw 8 个失败记录：

1. note-on/note-off 表征：飘音
2. grammar-masked：慢
3. 噪声数据放大：没用
4. Mirostat：减重复但紊乱
5. extra local auxiliary：无收益
6. 绝对 scalar：没 pairwise 准
7. 验证 loss：漏了 rollout 质量
8. Born-again networks：没用

8 个失败 = 8 个失败 commit + 8 个 README 条目。

大公司 8 个失败：埋在 Jira 里，没人看。
一人工程 8 个失败：写在 GitHub README，所有评审者能看。

## fail 跟 success 的对照

solo engineer 选 fail + success 都写：

- fail：避免重复 + 给后来人参考
- success：演示技术 + 推广项目

simedw README 同时写 8 个 fail + 6 个 success（DPO β=0.03 偏好率 57.14% / β=0.10 偏好率 38.10% / β=0.03 内部 consensus 69.05% / Core ML 量化 / App Store 11 天 / HN show top）。

大公司 README 只写 success，不写 fail。

## fail 是一人工程的诚实

fail 文档是一人工程的诚实声明：

- 诚实：承认失败，不夸大
- 透明：公开失败，给社区参考
- 进步：从失败学，下次不再重复

simedw 8 个失败 commit = 8 个学习机会。下次实验避免这 8 个失败路径。

## 洞穴人第十三个代词

plink / note / training / ship / realtime / pipeline / readme / evaluation / love / privacy / future / quit / fail 十三层抽象：

- plink = 领域

- training = 方法
- ship = 部署
- realtime = 运行模式
- pipeline = 流程
- readme = 文档

洞穴人十三个词，描述 AI 音乐的十三个抽象层。

13 层 = 12 层 + 失败层。一人工程的 8 个失败 commit 是 13 层的真实数据。
