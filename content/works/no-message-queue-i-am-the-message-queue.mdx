团队有 message queue。

Message queue：异步消息传递。RabbitMQ：open source message broker。Kafka：distributed streaming platform。SQS：AWS simple queue service。SNS：AWS simple notification service。Redis Pub/Sub：in-memory pubsub。NATS：cloud native messaging。$0-$1000 / 月 in message broker.

每 startup 1 个 RabbitMQ + 1 个 Kafka + 1 个 event bus architect。$200K-$500K / 年。

solo engineer 没有 message queue。

我自己就是 message queue。

我想 publish 就 publish、想 subscribe 就 subscribe、想 queue 就 queue、想 consume 就 consume。我不需要 message queue、不需要 RabbitMQ、不需要 Kafka、不需要 SQS、不需要 SNS。

我没 message queue 的必要——访问量 1000 不需要 async。我没 RabbitMQ 的必要——没 RabbitMQ。我没 Kafka 的必要——没 Kafka。我没 SQS 的必要——没 AWS。我没 SNS 的必要——没 SNS。我没 Redis Pub/Sub 的必要——没 Redis。我没 NATS 的必要——没 NATS。我没 $0-$1000 / 月 的必要——Vercel free。我没 event bus architect 的必要——没 architect。我没 $200K-$500K / 年 的必要——没 message broker。

团队的 message queue 价值是「让 service 异步通信 + 解耦 + scale」。前提是有 microservices、需要解耦、需要 scale。solo engineer 没这个问题——访问量 1000、commit log 是异步、我 = 解耦。

一人工程的 message queue = git commit log + Vercel KV free。不是 RabbitMQ + Kafka $1000/月。
