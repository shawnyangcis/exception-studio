团队有 feature branch。

Feature branch：功能分支。Branching strategy：分支策略。Git flow：Vincent Driessen git flow.。GitHub flow：GitHub workflow.。Trunk-based development：trunk-based development.。Branch per feature：每个功能一个分支。Release branch：发布分支。$0 / 月 in branching.

每 startup 1 个 feature branch + 1 个 git flow + 1 个 merge conflict.。$50K-$200K / 年.

solo engineer 没有 feature branch。

我自己就是 feature branch。

我想 branch 就 branch、想 merge 就 merge、想 rebase 就 rebase、想 squash 就 squash。我不需要 feature branch、不需要 branching strategy、不需要 git flow、不需要 GitHub flow、不需要 trunk-based development、不需要 branch per feature、不需要 release branch.

我没 feature branch 的必要——我是 1 个 engineer 我直接 commit main。我没 branching strategy 的必要——没 strategy。我没 git flow 的必要——没 git flow。我没 GitHub flow 的必要——没 GitHub flow。我没 trunk-based development 的必要——没 trunk-based。我没 branch per feature 的必要——main = feature branch。我没 release branch 的必要——main = release branch。我没 $0 / 月 的必要——Vercel free + git。我没 merge conflict 的必要——没 conflict。我没 $50K-$200K / 年 的必要——没 branching infrastructure.

团队的 feature branch 价值是「让 feature 隔离 + 并行开发 + code review」。前提是有 multi-developer、需要 isolation、需要 review。solo engineer 没这个问题——我是 1 个 engineer、main = feature branch、commit log 是 review.

一人工程的 feature branch = git main + commit。不是 git flow + branch per feature + merge conflict team.
