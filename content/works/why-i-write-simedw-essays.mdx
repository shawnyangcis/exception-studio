# 为什么我写 simedw 系列

simedw（Simon Edwardsson）的项目写了 30+ 篇散文。
不只是为了 simedw。
是为了把「一人工程」的具体形态写出来。

# 一人工程的具体形态

「一人工程」不是抽象概念。
是具体形态：

- 一个人
- 一台机器
- 半年时间
- 一个明确问题
- 一个标准架构
- 一个表征创新
- 一个训练目标
- 一个部署目标
- 一个开源
- 一个发布

每一个具体形态都对应一篇散文：

- MIDI 单 token 5 个 head（表征创新）
- 踏板纳入 duration（训练目标）
- 数据清洗胜过 5× 堆量（数据）
- scheduled sampling（训练目标）
- DPO β=0.03（训练目标）
- iPhone 上 108 notes/sec（部署目标）
- INT8 量化（部署目标）
- 自动指标抓不出最佳模型（评估）
- continuation vs isolated 评估（评估）
- 14 次实验的耐心（过程）

每一篇散文是一个具体动作。
不是抽象讨论。
不是论文综述。
是 simedw 的真实代码 + 真实 rollout。

# 写散文的目的

simedw 的项目：

- 一个人做完了
- 写下了真实记录
- 公开 GitHub README
- 让 100+ 人能复现

我写散文的目的：

- 把 simedw 的具体动作写出来
- 让「一人工程」从抽象变具体
- 让其他人也能做「一人工程」

不是写论文。
不是写综述。
不是写新闻。

是写「一个人做完了一件事的笔记」。

签名：solus opus。
