## cwbrowser / Turtle 技术栈 9 个表征层

coolwulf cwbrowser / Turtle pre-alpha 0.01.3，2026 上半年发布。技术栈拆解：

| 模块 | 自己表征 / 借表征 | 来源 |
|---|---|---|
| HTML parser | 自己表征（Zig） | Turtle 自己 |
| DOM | 自己表征（Zig） | Turtle 自己 |
| CSS cascade | 自己表征（Zig） | Turtle 自己 |
| Box-model layout | 自己表征（Zig） | Turtle 自己 |
| Paint | 自己表征（Zig） | Turtle 自己 |
| JS VM | 借表征（V8） | Google V8 |
| Networking | 借表征（系统栈） | OS |
| 渲染后端 | 借表征（Core Graphics / Metal） | macOS |
| Ad/tracker blocking | 自己加默认（EasyList） | EasyList 项目 |

Turtle 自己写 5 个表征层（HTML / DOM / CSS / layout / paint），借 4 个表征层（V8 / 网络 / 渲染后端 / 系统），加 1 个默认（EasyList）。5 + 4 + 1 = 9 个表征层 = 浏览器引擎的全部表征层。6 / 9 ≈ 67% 自己表征 / 加默认，3 / 9 ≈ 33% 借表征。这是表征哲学最具体的「表征工作的诚实边界」。

## 表征哲学 #4：表征工作的诚实边界

Turtle 的 V8 embed 哲学是表征哲学 vol.4 的核心引述：

> Re-implementing a modern, JIT-compiling JS VM is a decade-scale project, so Turtle embeds Google's V8.

「重写一个现代 JIT JS VM 是 10 年级项目」= 借 V8。这是表征哲学的最诚实回答 — 不是「什么都自己写」也不是「什么都用现成的」，是「能自己表征的自己表征，10 年级项目借表征」。

solo engineer 表征工作的诚实边界：

1. **5 / 9 ≈ 67% 自己表征 + 加默认**：HTML / DOM / CSS / layout / paint 都是 1-2 年级项目，自己表征 ROI 极高。EasyList 自己加默认 = 浏览器用户真正关心的隐私表征。
2. **3 / 9 ≈ 33% 借表征**：V8 / 网络 / 渲染后端是 10 年级项目，借表征 ROI 极高。
3. **性能表征独立**：~2× faster than Chrome = 表征不变 + 实现变。性能表征不来自「换表征」，来自「同样的表征 + 不同的实现表征」。
4. **表征层覆盖度 = 6 / 10**：自己表征 + 加默认 = 6 个表征层。vol.1 simedw 1 / 10、vol.2 surya 4 / 10、vol.3 fzakaria 2 / 10。coolwulf 6 / 10 = 最高覆盖度。
5. **「感动自己」vs「造福大众」**：主观意义是 solo engineer 唯一引擎。

## coefu #1 哲学强 anchor + coolwulf 的表征回答

coefu #1（散文站 material bank #4 fold 决定保留）：

> 「能真正接受不同意见的人本来就少，能接受 LLM 这种自动喷子的，你觉得有几个？大部分搞一个东西出来，不是为了改变什么，只是给自己内心一个交代，是被动的。」
>
> 「重造一个浏览器硬刚 chrome，感动的是自己，对现实有什么意义？意义都是自己主观上给的，不是客观世界的。有这个时间和精力，优化一下 llama.cpp，修一个 hard bug，实现一个 big feature。造福大众，比一个可能不如 chrome 的浏览器，有现实意义多了。」

solo engineer 表征哲学回答：

**表征改变 > 局部优化。** 优化 llama.cpp 的 hard bug = 表征不变 + 局部优化。coolwulf 的 from-scratch 浏览器 = 表征改变。表征改变的现实意义 > 局部优化的现实意义 — 因为局部优化的天花板是「已有表征框架内的最后 5% 性能」，表征改变的天花板是「未被表征过的 layer 全部被打开」。

**主观意义是 solo engineer 的唯一引擎。** coefu 说「意义都是自己主观上给的」，这一句是 solo engineer 的第一公理 — 不是悲叹，是事实。优化 llama.cpp 的「现实意义」同样是主观的。solo engineer 不假装「造福大众」是客观的，solo engineer 接受「主观意义」是唯一引擎，然后把主观意义放在「表征改变」而不是「局部优化」上。

**「感动自己」不是贬义词，是 solo engineer 的核心 KPI。** 团队里 KPI 是「对客户的价值」「对业务的影响」— 客观可量化。solo engineer 没有团队 KPI，KPI 只能是「对自己是否还感动」。coolwulf 13 年还在写浏览器 = coolwulf 还被自己感动。vol.1 simedw「算了，挺快乐」= simedw 接受「挺快乐」作为 solo engineer KPI 的达标。

## 「表征工作的诚实边界」三层解读

### 层次 1：技术边界（coolwulf 的 5 + 3 + 1 准则）

HTML / DOM / CSS / layout / paint 都是 1-2 年级项目，自己表征 ROI 极高。V8 / 网络 / 渲染后端是 10 年级项目，借表征 ROI 极高。1 个加默认（EasyList）= 浏览器用户真正关心的隐私表征。

solo engineer 的技术边界：能自己表征的自己表征，10 年级项目借表征。表征工作的诚实边界 = 知道哪些能自己表征、哪些借表征、哪些加默认。

### 层次 2：哲学边界（coefu #1 的「感动自己」 vs solo engineer 主观意义）

「感动自己」是 solo engineer 的核心 KPI。主观意义是 solo engineer 的唯一引擎。表征改变 > 局部优化。

solo engineer 的哲学边界：表征改变是「主观意义」的放大器，局部优化是「主观意义」的缩小器。coolwulf 选表征改变，不选 llama.cpp 局部优化，是哲学边界选择，不是技术能力选择。

### 层次 3：现实边界（散文站主轴 = 「一人公司 + 一人工程 + solitude」）

散文站不重新表征 React / Next.js（借表征）。散文站自己表征 = MDX 文件 + frontmatter + commit log。散文站加默认 = cover 字段允许 mp4 + slug 短链。散文站主观意义 = 「一人公司 + 一人工程 + solitude」。

solo engineer 的现实边界：能自己表征的 5 个 + 借表征的 4 个 + 加默认的 1 个 = 10 个表征层里 solo engineer 只能做 5-6 个。vol.4 coolwulf 的 5 + 4 + 1 = 10 / 10 = 完整表征。vol.1 simedw 只能做 1 / 10（compound note events）。vol.2 surya 只能做 4 / 10。vol.3 fzakaria 只能做 2 / 10。散文站只能做 3 / 10。

solo engineer 的现实边界 = 表征层覆盖度 = solo engineer 主观能动性的真实边界。
