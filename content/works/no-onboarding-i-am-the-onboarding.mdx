solo engineer 没有 onboarding。

大公司做 onboarding：

- **新员工培训**：HR 主导 1 周培训（公司文化 / 安全 / 福利）
- **buddy 系统**：每个新员工配 1 个 buddy（熟悉公司的老员工）
- **mentor 系统**：每个新员工配 1 个 mentor（技术 leader）
- **第一周不上班**：新员工第一周不上班，只学公司流程
- **onboarding doc**：100 页 onboarding doc（新员工必读）
- **内部 wiki**：Confluence / Notion 上 1000 页 wiki
- **部门介绍**：每个部门 1 小时介绍
- **codebase tour**：mentor 带新员工走 codebase

一人工程做 onboarding：
- 没有新员工
- 没有 buddy
- 没有 mentor
- 没有 onboarding doc
- 没有内部 wiki

## simedw 的 onboarding 哲学

simedw 是 iPhone piano app。他没有 onboarding：

- **simedw 不需要新员工**：simedw 自己 = 团队
- **simedw 不需要 buddy**：simedw 自己 = buddy
- **simedw 不需要 mentor**：simedw 自己 = mentor
- **simedw 不需要 onboarding doc**：simedw 写代码时知道所有架构
- **simedw 不需要内部 wiki**：simedw 脑子里就是 wiki

simedw 的"onboarding"在 git log + commit message + HN 评论里：

- **git log**：所有 commit 时间 + 内容
- **commit message**：每个 commit 的 why / what
- **HN 评论**：simedw 自描述 simedw 的 progress
- **README**：simedw 项目简介

如果 simedw 突然消失，新 maintainer 可以：
- 读 git log（了解历史）
- 读 commit message（了解每次改动）
- 读 HN 评论（了解 simedw 思路）
- 读 README（了解项目结构）

不需要 100 页 onboarding doc。

## 一人工程的 onboarding 工具

- **git log**：所有 commit 时间 + 内容
- **commit message**：每次改动的 why
- **README**：项目简介 + 架构
- **HN / 博客**：simedw 自描述
- **HN 评论**：其他 developer 的反馈

不需要 Confluence / Notion wiki，因为：
- 开发者 = 唯一的 maintainer
- 开发者脑子里 = wiki
- 不需要给新员工写 onboarding

## onboarding 在大公司的政治

onboarding 不是工具——是**知识转移工具 + 政治工具**：

- **HR**：要用 onboarding 减少新员工流失
- **mentor**：要用 onboarding 表现 leadership
- **buddy**：要用 onboarding 学新人 + 表现 collaboration
- **CTO**：要用 onboarding 加速新员工产出
- **PM**：要用 onboarding 让新员工快速上手
- **新员工**：要用 onboarding 学公司

每个 stakeholder 都要 onboarding：

- HR onboarding = "新员工不流失"
- mentor onboarding = "我表现 leadership"
- buddy onboarding = "我学新人"
- CTO onboarding = "新员工快速产出"
- PM onboarding = "新员工快速上手"
- 新员工 onboarding = "我学公司"

没有 onboarding = 没有知识转移 = 新员工慢产出。

一人工程没有 stakeholder：
- 开发者 = HR = mentor = buddy = CTO = PM = 新员工
- 一个人 onboarding
- 不需要 100 页 doc

## onboarding doc 在大公司的细节

大公司 onboarding doc 通常 100 页：

- **公司介绍**：mission / vision / culture / history
- **部门介绍**：每个部门 1-2 页
- **代码库介绍**：架构 + 模块 + 工具链
- **开发流程**：git workflow + CI/CD + deploy
- **工具介绍**：Slack / Jira / Confluence / Notion / Linear
- **福利介绍**：health insurance / 401k / PTO
- **法律介绍**：NDA / IP assignment / GDPR

每个 onboarding doc：

- 100 页
- HR 维护
- 每季度更新

一人工程没有 onboarding doc。一人工程有：

- **simedw 的 README**：项目简介（1 页）
- **simedw 的 commit message**：每次改动（git log）
- **simedw 的 HN 评论**：simedw 思路

README + commit message + HN = 100 页 onboarding doc 的**最小子集**。

## buddy 系统在大公司的细节

大公司 buddy 系统——每个新员工配 1 个 buddy：

- **buddy 职责**：回答新员工日常问题（"在哪里吃饭" / "Slack 在哪" / "GitHub 仓库在哪"）
- **buddy 时长**：3 个月（之后新员工独立）
- **buddy 配对**：HR 配对（基于团队 / 兴趣 / 性格）

每个 buddy：

- 每周回答 5-10 个问题
- 帮新员工介绍团队
- 帮新员工熟悉工具

一人工程没有 buddy。一人工程有：

- **simedw 自己就是 buddy**：simedw 问自己 + 自己答
- **simedw 不需要 HR 配对**：simedw 自己决定
- **simedw 不需要 3 个月**：simedw 没有 buddy 时长

不需要 buddy，因为 simedw 自己 = buddy。
