团队 manager 跟 IC 每周 1:1 30 分钟。

manager 准备 agenda：career development（你接下来想 grow 哪块？）、blocker（什么事卡住你？）、feedback（哪些做得好、哪些要改）、project context（下一个 sprint 你的 focus 是什么？）。IC 准备 status update、career question、blocker list。

1:1 的存在是为了**让 manager 和 IC 之间有 private 沟通渠道**——避开团队公开场合，让 IC 能诚实暴露困惑、manager 能 honest feedback。

manager 的核心职责：**让 IC grow**——assign stretch project、remove blocker、give feedback、align incentive。

一人工程没有 1:1。

simedw 自己 = manager + IC。simedw 自己跟自己 1:1 不会有 career conversation（career = 自己的，不跟 manager 谈）、不会有 blocker list（blocker = 自己的，不跟 manager escalate）、不会有 project context alignment（context = 自己的，不跟 manager sync）。

> 一人工程的 1:1 是 simedw 自己跟自己 + git log。

simedw 的「career development」是 `git log --since="1 year ago" | grep "feat:" | wc -l` —— 一年 ship 多少新 feature = simedw 的 career growth 指标。simedw 的「blocker」是 `git log --since="1 week ago" | grep "fix:" | wc -l` —— 一周多少 fix = simedw 的 blocker 严重程度。simedw 的「feedback」是 App Store reviews —— 用户 5 星 4 星 vs 1 星 2 星 = simedw 的 honest feedback。

团队 1:1 的存在是因为 **5-10 个 IC 不能 everyone 自己跟 manager 谈**——manager = 1 人，10 个 IC，每人每周 30 分钟 = 5 小时 manager 工时。一人工程 simedw 没有这个工时浪费——simedw 自己谈自己，0 工时。

vladislav-kalinkin 的 Ullis 没有 1:1——vladislav 自己 = maintainer + 自己 career 决策者。

andalabx 的 Clean skill 没有 1:1——andalabx 自己 = skill author + 自己 sponsor 关系维护。

> 团队的 1:1 让 manager 帮 IC grow。一人工程 simedw 自己 career grow，没有 manager 必要。

trade-off：团队 1:1 让 manager external perspective 帮 IC 看到 blind spot。一人工程 simedw 没有 manager external perspective，blind spot 通过 App Store reviews 暴露。

solo engineer 接受这个 trade-off——simedw 不需要 manager 帮自己看 blind spot，App Store 用户已经帮他看。

solo engineer 的 1:1 是 git log + App Store reviews + self-questioning。

solus opus.
