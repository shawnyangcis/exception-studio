solo engineer 没有 CDN。

大公司做 CDN (Content Delivery Network)：

- **Cloudflare / Fastly / AWS CloudFront / Akamai**：CDN 服务商
- **edge caching**：在全球 100+ 节点缓存静态资源
- **SSL termination**：CDN 终止 SSL
- **WAF**：Web Application Firewall（防 SQL injection / XSS）
- **DDoS protection**：防大规模流量攻击
- **image optimization**：CDN 自动压缩 / 转换图片格式
- **video streaming**：CDN 流式传输视频（HLS / DASH）

一人工程做 CDN：
- 没有 Cloudflare
- 没有 Fastly
- 没有 WAF
- 没有 DDoS protection
- 没有 image optimization

## simedw 的 CDN 哲学

simedw 是 iPhone piano app。他没有 CDN：

- **App Store = CDN**：苹果 App Store 在全球分发 iPhone app，比任何 CDN 都广
- **iPhone 本地运行 app**：app 在用户 iPhone 上运行，不需要 edge caching
- **simedw 没有 SSL**：iPhone app 没有 web SSL
- **simedw 没有 WAF**：iPhone app 不接受 web 流量
- **simedw 没有 DDoS**：iPhone app 不能被 DDoS 攻击（本地运行）
- **simedw 没有 image optimization**：iPhone app 没有 web 图片

simedw 的"CDN"在苹果 App Store + iPhone OS：

- **App Store 全球分发**：苹果在 175+ 国家分发 iPhone app
- **App Store 自动更新**：苹果自动推送新版本
- **iPhone OS 自动安装**：用户 iPhone 自动下载 + 安装
- **iPhone 本地缓存**：用户 iPhone 本地存 app，不需要 edge caching

不需要 Cloudflare，因为：
- 苹果 App Store 是全球最大 CDN（10 亿 iPhone 用户）
- iPhone app 本地运行 = 0 网络流量
- iPhone OS 自动处理 app 分发 = edge caching

## edge caching 在大公司的细节

- **cache invalidation**：清除缓存（URL purge / tag purge）
- **stale-while-revalidate**：缓存过期后仍返回旧值 + 后台刷新

每个 edge caching：

- 全球 100-4000+ 节点
- 几 TB 缓存
- 几毫秒延迟

- **simedw 0 网络延迟**：iPhone 本地运行 = 0 ms 延迟
- **simedw 不需要 cache invalidation**：iPhone app 不能远程清除本地缓存
- **simedw 不需要 TTL**：iPhone app 不需要过期

## iPhone app vs web app 的 CDN 区别

iPhone app 和 web app 根本不同：

- **web app**：用户浏览器 → CDN → origin server（每次请求都走网络）
- **iPhone app**：用户下载 → iPhone 本地运行（0 网络流量）

simedw 的 iPhone piano app：

- 用户下载 app 一次（约 100 MB）
- app 在 iPhone 本地运行（0 网络）
- 不需要每次请求都走 CDN
- 不需要 edge caching
- 不需要 WAF

不需要 Cloudflare，因为：
- simedw 的 app 没有 web 流量
- iPhone 本地运行 = 0 网络
- App Store = 全球最大 CDN
