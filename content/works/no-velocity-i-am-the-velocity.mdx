solo engineer 没有 velocity。

大公司做 velocity：

- **velocity 定义**：sprint 完成 story point 数 / sprint
- **velocity 测量**：每个 sprint 末计算
- **velocity 比较**：跨 sprint / 跨团队 / 跨部门
- **velocity 预测**：基于历史 velocity 预测未来 sprint 能完成多少
- **velocity benchmark**：团队 / 部门 / 公司的平均 velocity
- **velocity 评估**：HR 用 velocity 评估团队 / 个人绩效

一人工程做 velocity：
- 没有 story point
- 没有 sprint
- 没有 benchmark
- 没有 HR 评估

## simedw 的 velocity 哲学

simedw 是 iPhone piano app。他的"velocity"在 git log 里：

- **commit 1**：exp 1 standard cross-entropy baseline（2026 年某月某日）
- **commit 2**：exp 2 compound note events 5× speedup（同月）
- **commit 3**：exp 3 DPO preference optimization（同月）
- **commit 4**：exp 4 β=0.03 vs β=0.10（同月）
- ...
- **commit 14**：exp 14 DPO main 接续度

14 个 commit / 6 个月 = **simedw 的 velocity = 14 个实验 / 半年**。

git log 是 simedw 的 velocity dashboard：
- 每次 commit = 1 个 story point（自我估算）
- 每天 commit 数 = 当天 velocity
- 每周 commit 数 = 当周 velocity
- 每月 commit 数 = 当月 velocity

不需要单独的 velocity 工具，因为 git log 就是。

## 一人工程的 velocity 工具

- **git log**：commit 频率 = velocity
- **commit 时间戳**：commit 时间 = 工作节奏
- **commit message**：commit 内容 = 工作内容
- **git diff**：每次 commit 改动 = velocity 单位

不需要 Jira sprint board，因为 git log 够了。

## velocity 计算在大公司的必要性

大公司 velocity 计算：

```
velocity = sprint 完成 story point 总数 / sprint 时长

sprint 1: 30 story point / 2 weeks = 15 story point / week
sprint 2: 32 story point / 2 weeks = 16 story point / week
sprint 3: 28 story point / 2 weeks = 14 story point / week
average velocity: 15 story point / week
```

每个 velocity：

- 团队稳定后计算
- 跨 sprint 比较
- 跨团队 benchmark

一人工程没有 velocity 计算。一人工程有：

- **simedw 14 commit / 6 个月**：14 / 26 周 = 0.54 commit / 周 = simedw 的 velocity
- **不需要 sprint**：simedw 没有 sprint
- **不需要 benchmark**：simedw 没有团队比较

git log 直接算。

## velocity 的失败模式

大公司 velocity 经常失败：

- **velocity inflation**：sprint 末 PM 加简单任务拉高 velocity
- **velocity gaming**：工程师拆分任务（5 点拆成 2+3）让 velocity 高
- **story point inflation**：今年 5 点 = 去年 8 点（团队熟练后估算变松）
- **velocity pressure**：scrum master 给团队施压达到 velocity target
- **velocity 错误归因**：velocity 高 = 团队好，但实际可能是 sprint 内容简单

velocity 失败的解法：
- 跨团队 velocity 校准
- velocity 与奖金脱钩
- 公开 velocity（防止 inflation）

一人工程没有 velocity 失败模式，因为：
- simedw 没有 inflation（自己骗自己没意义）
- simedw 没有 gaming（自己拆分任务浪费时间）
- simedw 没有 story point inflation（没有 story point）
- simedw 没有 pressure（自己给自己施压 vs scrum master）
- simedw 没有错误归因（自己归因）

velocity 在一人工程里 = **git log commit 频率**，没有失败模式。
