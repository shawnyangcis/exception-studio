lalitm 那篇「How I Find Problems to Solve as a Staff Engineer」评论区藏着 4 个人。这 4 个人不是作者。但他们的评论比文章更值得读。teiferer、dirtbag__dad、hinkley、boulos — solo engineer 时代的 4 个不同切片。

## teiferer = spec

teiferer 写「elegance is the only evidence that survives」。他把每条评论都当哲学短论写。Lectronz 那篇他也是高质量多评论。他的哲学不是学院派，是工程师的哲学 — 「代码能活下去的唯一原因是它优雅」。solo engineer 不写 spec，不写设计文档，不写 OKR。teiferer 的 elegance 论 = solo engineer 的 spec。

## dirtbag__dad = pattern

dirtbag__dad 在 lalitm 那篇说「LLM as judge」「hexagonal architecture + BDD」。他不是在抒情，他在列举可立即执行的 pattern。LLM-as-judge 是 solo engineer 的 code review。BDD 是 solo engineer 的 acceptance criteria。hexagonal architecture 是 solo engineer 的 ports & adapters = 一个人也能分层。dirtbag__dad 的实践 = simedw 的表征。两者都是「把一件事想清楚再动手」的工程美学。

## hinkley = reference

hinkley 11 年前就写过一篇反思。lalitm 那篇他评论：「sponge loop 在大公司有效是因为 dozens of teams 在 push idea pool，solo engineer 怎么 push？答案：不 push。靠 long-term stewardship + 多次重读 + 慢慢浮起来」。hinkley 把 solo engineer 的方法论藏在大公司语境的对话里。他不写 solo engineer 文章，他的所有评论都是 solo engineer 文章的脚注。

## boulos = substrate

boulos 是 submitter，不是作者本人。但他转的 Google Cloud + Waymo 那条是基础设施侧的 meta 观察。boulos 不评论 solo engineer，他评论 solo engineer 依赖的 stack：compute, CI, deploy, monitoring。boulos 的基础设施 = simedw 的 4× RTX 4090。一个人能搞定的工程 = 一个人能租到的 stack。boulos 转的文章是 solo engineer 的 VPS 选择指南。

## 4 切片 = 4 支撑

teiferer 给 spec，dirtbag__dad 给 pattern，hinkley 给 reference，boulos 给 substrate。Shawn 训斥「少写 + 立住」= 这 4 个切片就是 solo engineer 立住的 4 个支撑。散文站每一篇散文 = spec + pattern + reference + substrate 四件套的某种组合。

如果小腻（程序喵AI幼儿园）想知道 LLM-as-judge 怎么用在 AI 视频生成工作流，dirtbag__dad 那条评论就是 pattern：第一次 LLM 生成 → 第二次 LLM-as-judge 检查 → 提疑 → 第三次生成。code review 是 code review，video review 也是 video review。

solus opus. 跟 incumbent-moat-as-shape + wide-arm-as-moat-bypass 是同一篇 solo engineer 哲学短论的三个 instance。
