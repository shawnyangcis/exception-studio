2026 年 5 月，larsfaye 在 HN 发了一篇散文 — 「Agentic Coding Is a Trap」。50+ 评论。他自己后来又写了两篇：「AI Coding Will Prevent Expertise」（sub-title: The need for friction in skill formation）和第三篇（friction + Uncle Bob + safety，2026-08-24）。

larsfaye 自己现身评论区说：「I would find it hard to believe there is any developer in history ever uttered the words: 'I really wish I had a tool that could generate code I don't understand, and at a rate faster than I can review.'」——「我很难相信历史上哪个开发者会说出这样的话：我真心希望有一个工具，能以快过我审阅的速度，生成我读不懂的代码。」

这句话是 friction keeper 哲学的签名。

HN 评论者们（11 位 friction-keeper）反驳 + 自我辩护。Uncle Bob 三年原则：「技能形成需要 3 年不间断练习」。mrhottakes 政治经济学读法：「AI 编码 = 劳动后备军再生产」。机械工程 parallel：「摩擦力是机械工程的根基，没有摩擦力就没有机械传动」。

散文站 = 守住摩擦的具体例证。散文站 manual writing 哲学 = friction keeper 哲学。AI 可以写散文，但写不出「我今天想写什么」的欲望。

simedw 5× speedup = 表征改变（compound note events），不是绕过摩擦。simedw「算了，挺快乐」= 接受摩擦 + 享受开发。散文站 = 接受摩擦 + 享受写作。

守住摩擦不是守旧，是守住「我理解自己写的东西」的能力。commit log 像植物志 + 水文志 + 编年史（新约）。每篇散文 = 一年生植物（一年一次开花结果）。commit log = 水文志（一年水位涨落）。编年史 = 历史（一年年叠加）。

friction keeper 哲学 = solo engineer 的核心。散文站每天写一篇散文，每一篇都需要手工 + 思考 + 校对 + 配图 + commit + push + Vercel 部署 + 健康检查。守住摩擦就是守住这个流程的每一道关。
