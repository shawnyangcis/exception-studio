solo engineer 公开失败需要勇气。

失败不是羞耻，公开失败需要诚实 + 勇气 + 决策。

## 公开失败需要什么

公开失败需要 3 个东西：

1. 诚实：承认失败，不夸大
2. 勇气：写下来，公开
3. 决策：承担公开的后果

3 个缺一不可。

## 诚实的部分

诚实 = 承认失败，不夸大。

simedw 在 README 写：

- note-on/note-off 表征：飘音
- grammar-masked：慢
- 噪声数据放大：没用
- Mirostat：减重复但紊乱
- extra local auxiliary：无收益
- 绝对 scalar：没 pairwise 准
- 验证 loss：漏了 rollout 质量
- Born-again networks：没用

8 个失败 = 8 个诚实的描述。

没有「失败但我们尽力了」，没有「失败是有意义的探索」，没有「失败的教训让我们成长」。只有「没用」、「飘音」、「慢」、「紊乱」、「无收益」。

8 个直接诚实的描述 = simedw 的诚实。

## 勇气的部分

勇气 = 写下来，公开。

8 个失败写进 README，让 HN show 评审者 + GitHub 用户 + App Store 用户都能读到。

公开失败 = 暴露自己的弱点。

solo engineer 公开失败的勇气：

- 在 HN show 评论者前承认失败
- 在 App Store 评价前承认失败
- 在未来 solo engineer 学习者前承认失败
- 在求职 / 招聘前承认失败

4 个公开场景 = 4 个勇气时刻。

## 决策的部分

决策 = 承担公开的后果。

公开失败的后果：

- HN show 评审者降低评分
- 招聘方降低评分
- 用户降低信任
- 自己承担失败情绪

4 个后果 = solo engineer 公开失败的代价。

但 solo engineer 接受代价，因为：

- 诚实 > 评分
- 公开 > 私密
- 失败 > 假装成功

3 个「>」 = solo engineer 公开失败的决策。

## 公开失败的勇气 = solo engineer 的正常选项

solo engineer 公开失败不是英雄，是正常选项。

每个 solo engineer 都会失败，区别在公开不公开。

公开失败 = solo engineer 的诚实 + 勇气 + 决策。

私密失败 = 大公司的 5 个私有（失败清单私有）。

solo engineer 选公开失败。

## 跟私密失败的对照

大公司私密失败：

- Sprint review 悄悄提及失败
- PR 隐藏失败 commit
- 内部文档隐藏失败
- 设计 review 隐藏失败
- 复盘会议隐藏失败

5 个隐藏 = 大公司的私密失败。

solo engineer 公开失败：

- README 公开失败清单
- Commit 公开失败 commit
- HN show 评论公开失败
- App Store 评价不隐藏失败
- 失败清单 = 8 个公开

5 个公开 = solo engineer 的公开失败。

两个文化：私密失败 = 假装成功，公开失败 = 真实进步。

## 一人工程的失败勇气哲学

solo engineer 失败勇气哲学：

- 失败不是羞耻（不是 PR 隐藏的）
- 失败不是弱点（不是 review 隐藏的）
- 失败不是秘密（不是 sprint 隐藏的）
- 失败是诚实（公开失败 = 真实）

4 个不是 = solo engineer 失败勇气哲学。

## 跟洞穴人格式的关联

洞穴人格式第十二篇 quit = 退出哲学。

solo engineer 公开失败 + quit 的勇气 = solo engineer 完整的勇气 cycle。

公开失败 → 公开失败清单 → 公开失败反思 → 公开退出或继续。

4 个公开 = solo engineer 勇气 cycle。

- 诚实：承认失败，不夸大

3 个 = solo engineer 公开失败的勇气。

公开失败不是英雄，是 solo engineer 的正常选项。
