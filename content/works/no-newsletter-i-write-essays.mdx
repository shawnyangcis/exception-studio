团队有 newsletter。

Substack：每周一篇邮件。Email digest：每月一次汇总。Weekly roundup：每周推荐 5 篇文章。RSS feed：自动生成 XML。Newsletter tool：ConvertKit / Mailchimp / Beehiiv。

每周末写一篇 newsletter。订阅者 1000-50000。

solo engineer 没有 newsletter。

我直接写散文。

commit message + 散文列表就是我的 newsletter。我写了 no-canary-deploy，访问者 RSS 订阅、收到通知。我写了 no-deploy-freeze，访问者主页看到。

我没 Substack 的必要——没订阅者。我没 email digest 的必要——没 email list。我没 weekly roundup 的必要——我每篇散文都是 roundup。我没 RSS feed 的必要——Vercel 自动生成 sitemap.xml。

团队的 newsletter 价值是「持续触达 + 建立读者关系」。前提是订阅者多、需要持续曝光、需要 email list。solo engineer 没这个问题——访问者直接看主页、关注 git commit、commit = push notification。

一人工程的 newsletter = `git log`。不是每周邮件。
