团队有 status update。

Status update：每周 / 每天 1 次状态。Weekly update：周五发。Daily update：每天发。6.000 emails：每天 6000 封邮件。Team update：群发所有 team。Standup report：3 句话。Manager update：1-on-1 之前。Director update：board 之前。

每员工每周 1-3 次 status update + 写 30 分钟 + 读 10 个同事的 update。

solo engineer 没有 status update。

我自己 commit。

我 commit = status update。commit message = what I did yesterday + today + blockers。我不需要 6.000 emails、不需要 weekly update、不需要 daily update。

我没 status update 的必要——没 manager 要 read。我没 weekly update 的必要——没 team 要 align。我没 daily update 的必要——没同事要 coordinate。我没 6.000 emails 的必要——我没 6000 个 recipient。我没 team update 的必要——没 team。我没 standup report 的必要——没 standup。我没 manager update 的必要——没 manager。

团队的 status update 价值是「让 manager 知道进度 + 跨 team 协调」。前提是有 manager、需要 visibility、需要 cross-team。solo engineer 没这个问题——我没 manager、不需要 visibility、commit log = cross-team。

一人工程的 status update = git commit log。不是 6.000 emails。
