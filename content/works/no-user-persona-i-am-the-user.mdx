团队有 user persona。

User persona：「Sarah，28 岁，NYC，产品经理，喜欢读 Substack」——一类用户的抽象。Target audience：「25-35 岁 urban professional」。Customer profile：年龄 / 职业 / 收入 / 兴趣 / 痛点。Buyer persona：谁决定买。Empathy map：用户想什么 / 说什么 / 做什么 / 感觉什么。

每季度做一次 user research、更新 persona。3 周。

solo engineer 没有 user persona。

我自己就是用户。

我自己 build、我自己看、我自己感受。我写了 no-deploy-freeze，我打开浏览器读一遍，我 = 用户。我写了 no-canary-deploy，我点开看，我 = 用户。我不需要「Sarah, 28 岁, NYC」来告诉我用户怎么想。

我没 user persona 的必要——我自己就是 persona。我没 target audience 的必要——访问者自己来。我没 customer profile 的必要——没人买产品。我没 buyer persona 的必要——没 buyer。我没 empathy map 的必要——我写散文时就是 empathy。

团队的 user persona 价值是「让团队成员理解目标用户」。前提是成员多、需要 alignment、需要用户视角。solo engineer 没这个问题——我 build 时 = 用户 = engineer 三合一。

一人工程的 user persona = 我自己。不是「Sarah, 28 岁, NYC」。
