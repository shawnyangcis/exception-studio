团队有 twitter。

Tweet：280 characters。Thread：长推串。Social media：Twitter / Mastodon / Threads。Followers：1000+。Viral：偶尔一条 tweet 上 trending。

每条产品 launch 发一条 thread。1-3 周一次。

solo engineer 没有 twitter。

我直接写散文。

commit message + 长散文就是我的 twitter。我写了 no-canary-deploy，commit message 描述完整想法。我写了 no-deploy-freeze，访问者点开 `/works/no-deploy-freeze` 看完整 1500 字。

我没 280 characters 的必要——我写 1500 字散文。我没 thread 的必要——散文就是 thread。我没 followers 的必要——访问者自己来看。我没 viral 的必要——viral 不等于 quality。

团队的 twitter 价值是「触达 + 营销 + 引流」。前提是 follower 多、需要 marketing、需要 brand awareness。solo engineer 没这个问题——我的 marketing = 散文质量本身、commit log 是 timeline、git push 是 notification。

一人工程的 twitter = `git commit`。不是 280 characters。
