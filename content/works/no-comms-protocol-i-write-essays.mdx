团队有 comms protocol。

Communication protocol：通信协议。Comms plan：通信计划。Notification system：通知系统。Slack channel：100 个 channel。Escalation path：升级路径。On-call alert：phone 响。Incident comms：事故时通信。Paging system：page 工程师。Email thread：邮件来回。

每 startup 1 个 Slack workspace + 100 个 channel + 1 个 incident comms playbook + 1 个 on-call pager。

solo engineer 没有 comms protocol。

我自己写散文。

我写散文 = 我在做 comms。访问者点开看 = 我在做通知。我不需要 Slack channel、不需要 escalation path、不需要 on-call alert、不需要 incident comms。

我没 comms protocol 的必要——没 100 个同事。我没 comms plan 的必要——没 team 要 align。我没 notification system 的必要——没 notification 要 send。我没 Slack channel 的必要——没 channel 要 monitor。我没 escalation path 的必要——没 escalation。我没 on-call alert 的必要——我不 on-call。我没 incident comms 的必要——我 = comms。我没 paging system 的必要——我 = page。我没 email thread 的必要——我没邮件要回。

团队的 comms protocol 价值是「让 team 知道谁在做什么 + 快速对齐」。前提是有 team、需要 alignment、需要跨时区。solo engineer 没这个问题——没 team、不需要 alignment、散文 = comms。

一人工程的 comms protocol = 散文 + commit log。不是 100 个 Slack channel。
