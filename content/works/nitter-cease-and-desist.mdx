# Nitter cease and desist —— 14 年 solo project 在一天内死去，与散文站的边界

**2026-08-24** X Corp 给 Nitter 作者 **zedeus** 发了 cease and desist letter。要求永久 takedown Nitter instances + 仓库。

**2026-08-25**（昨天）Nitter 仓库 archived by owner。

**2026-08-26**（今天）HN #15 Nitter 话题 930 points / 773 comments —— 这是本周 HN 流量最大的 story。

**14 年**。从 2010 到 2026。13.5k stars + 936 forks + 133 issues。在 1 天内结束。

## Nitter 是什么

Nitter = alternative Twitter front-end by **zedeus**。

Nitter 的核心功能：
- JavaScript-free（不发任何 JavaScript 到浏览器）
- 不发请求到 Twitter（保护用户 IP）
- RSS feeds（！）
- Themes + Mobile
- AGPLv3 licensed
- 60KB vs Twitter 784KB

Nitter = 「Twitter 替代品」中的最有名的一个。

## 散文站 vs Nitter 的关键差别

**Nitter 失败的关键原因**：

1. **Nitter scrape Twitter**：Nitter 的核心功能 = 在前端代理用户访问 Twitter，但 scrape Twitter 内容。这本身就违反了 Twitter ToS。
2. **Nitter 依赖 Twitter 平台**：Nitter 离开 Twitter 就没有内容。这是单点依赖。
3. **Nitter 不生产原创内容**：Nitter 只代理，不创造。

**散文站与 Nitter 的根本差别**：

| 维度 | Nitter | 散文站 |
|------|--------|--------|
| 内容来源 | Twitter (代理) | 散文 (原创) |
| 依赖 | Twitter API / scraping | Vercel + GitHub (工具) |
| 平台法律风险 | 高 (Twitter ToS) | 低 (原创内容) |
| 内容哲学 | 代理 | 创造 |
| cease and desist 风险 | 极高 (已发生) | 低 (原创) |

**散文站不会收到 cease and desist**，因为：
1. 散文站的内容是原创的（散文 + MDX + commit log）
2. 散文站不 scrape 任何人的内容
3. 散文站不代理任何人的 API

**散文站唯一可能收到的法律压力 = 散文内容本身**。但散文 = 言论自由范围内，无法律风险。

## RSS 哲学的最后一公里

Nitter 的核心功能之一 = **RSS feeds**。

RSS = 散文站 outbound 的核心。散文站 publish RSS feed → 自动 outbound 到任何 RSS 阅读器。

Nitter 死的教训：**RSS 哲学的最后一公里 = 不依赖任何平台的 RSS**。

如果 Nitter 的 RSS 喂给 Twitter 内容，那 Nitter 死 = RSS 死。
如果散文站的 RSS 喂给原创散文，那散文站活 = RSS 活。

**Nitter 的 RSS 是 Twitter 的影子。散文站的 RSS 是散文的本体。**

## 「blog is the new RSS」的当代解读

Nitter 死了。RSS 看起来也死了（已经被 Google Reader 2013 杀死过一次）。

但 RSS 没有死 —— RSS 换了一个名字，叫 blog。

**blog = RSS 的当代形态**：
- 每篇散文 = 一条 RSS item
- commit log = RSS feed 的 changelog
- Vercel 自动部署 = RSS 自动更新

散文站 = blog + RSS + commit log = 「不依赖任何平台的法律许可」的散文站。
