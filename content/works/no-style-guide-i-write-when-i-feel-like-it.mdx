团队有 style guide。

Google JavaScript Style Guide、Airbnb JavaScript Style Guide、PEP 8、Effective Go、black、prettier、ESLint、Google Java Style、SwiftLint、RuboCop。

每个 PR 强制过 lint。code review 第一关：「风格不符合，reject」。新人入职读 50 页风格手册。

solo engineer 没有 style guide。

我想怎么写就怎么写。

tab 还是 space、单引号还是双引号、trailing comma 还是不 trailing、变量名 camelCase 还是 snake_case——我决定。

我没 linting rules 的必要——我读一遍比 linter 准。我没 prettier config 的必要——我自己决定怎么排版。我没 50 页风格手册的必要——风格手册 = 我脑子里的偏好。

团队的 style guide 价值是「多人协作保持代码一致」。前提是成员多、需要多人协作、需要 collective code ownership。solo engineer 没这个问题——我的代码只有我自己写、我自己读、我自己维护。

一人工程的 style = commit history。不是 50 页风格手册。
