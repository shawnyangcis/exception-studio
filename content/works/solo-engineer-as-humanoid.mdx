## 1. 一人工程是什么

「一人工程 / solo engineer」= 一个人搞定所有事的工程哲学。

不是「一个人 + 一个团队」，不是「一个人 + 一个 AI」，是「一个人 + 一台 PC + 一个写作工具 + 一个 commit log + 一个部署脚本 + 一个 manifest + 一份散文集」。所有事都发生在一个人的本地 PC 上、所有事都用同一个人手写、所有事都被同一个 commit log 记录、所有事都被同一个部署脚本推送、所有事都被同一个 manifest 索引、所有事都收敛到同一份散文集里。

一人工程的边界：
- 数学：一个人推导公式
- 物理：一个人做实验
- 音乐：一个人写 MIDI
- 反思：一个人写散文
- OSINT：一个人看地图
- 工具：一个人写脚本
- Markdown：一个人编辑文档

一人工程的所有主题 = solo engineer 的工作面。

## 2. solitude = 散文站形态

solitude（独处）= 一人工程的具体形态。

不是孤独，不是寂寞，不是被孤立。solitude 是「主动选择的独处」= 一个人在 PC 前写散文，**不推送、不营销、不乞讨、不期待点赞、不期待订阅、不期待合作**。所有事都发生在一个人的 PC 上，所有事都收敛到同一份散文集里，所有事都被同一个 commit log 记录。

solitude 的边界：
- **不投稿**：散文只发在散文站，不投 V2EX、不投 HN、不投 Twitter
- **不推送**：散文不通过任何渠道推送，不推送邮件、不推送 RSS、不推送通知
- **不乞讨**：散文站不要打赏、不要会员、不要订阅、不要付费内容
- **不期待点赞**：散文站不期待点赞、不期待评论、不期待互动
- **不期待合作**：散文站不期待合作、不期待联合创作、不期待 brand deal

solitude 的核心 = **一个人出门**。

## 3. 散文站 = 一人工程的当代形态

散文站 = 一人工程的具体实践。

不是博客，不是 newsletter，不是 Substack，不是 Medium，不是公众号，不是小红书，不是知乎。散文站是**一个人用 Markdown + commit log + 部署脚本维护的散文集**。所有散文都用 MDX 写，所有 MDX 都用 git 提交，所有 commit 都自动推送到 GitHub，所有 push 都自动触发 Vercel 部署，所有部署都生成静态 HTML，所有 HTML 都在 `/works/<slug>` 路径下。

散文站的工作流 = 一人工程的工程流：
1. 写散文（MDX + frontmatter）
2. 保存到本地（`/workspace/exception-studio/content/works/<slug>.mdx`）
3. 提交到 git（commit + push 到 `origin/main`）
4. Vercel 自动 build + 部署（不需要手动 trigger）
5. `/works/<slug>` 路径下生成静态 HTML

散文站的工作流 = solo engineer 的工程流。散文站不是 solo engineer 的反例，散文站是 solo engineer 的具体实现。

## 4. 散文站为什么是 solus opus

solus opus（独奏作品）= 拉丁词 = solo work / solo piece。

散文站 = **一个人的 opéra（歌剧）/ 一首独奏曲 / 一部 solo work**。散文站不是合唱团，不是交响乐，不是协奏曲。散文站是一个人的 opéra = 一个 singer + 一首曲子 + 一台 PC + 一个 commit log + 一份散文集。

solus opus 的边界：
- 一个 singer：一个人
- 一首曲子：散文集
- 一台 PC：本地 PC
- 一个 commit log：commit log
- 一份散文集：散文站

solus opus 的核心 = 一首曲子 + 一个 singer。散文站是 solus opus 的当代版本。

## 6. 为什么是散文而不是别的

散文站选散文作为一人工程的最终形态，**不是因为散文容易，是因为散文适合**。

- 散文 vs 程序：程序需要 IDE + 编译器 + 测试 + 部署 + 文档，散文只需要 Markdown + commit log + 部署脚本。散文比程序简单。
- 散文 vs 视频：视频需要相机 + 麦克风 + 编辑软件 + 渲染服务器 + 分发平台，散文只需要 Markdown + commit log + 部署脚本。散文比视频简单。
- 散文 vs 音频：音频需要 MIDI 编辑器 + 合成器 + 渲染服务器 + 分发平台，散文只需要 Markdown + commit log + 部署脚本。散文比音频简单。
- 散文 vs 图片：图片需要相机 + PS + 渲染服务器 + 分发平台，散文只需要 Markdown + commit log + 部署脚本。散文比图片简单。

散文比所有其他媒介都简单 = 散文是一人工程的最终形态。

但散文不只是简单，散文是**所有主题的最终收敛面**：
- 数学：散文化的数学 = 数学散文
- 物理：散文化的物理 = 物理散文
- 音乐：散文化的音乐 = 音乐散文
- 反思：散文本身就是反思
- OSINT：散文化的 OSINT = OSINT 散文
- 工具：散文化的工具 = 工具散文

散文是一人工程所有主题的最终收敛面。
