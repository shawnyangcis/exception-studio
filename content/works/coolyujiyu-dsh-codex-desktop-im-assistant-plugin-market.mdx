## GitHub 仓库：88 commits + Apache 2.0 + 15 stars

仓库地址 `https://github.com/MichengAI/dsh-codex-desktop`，88 commits，Apache License 2.0，15 stars，0 forks，多平台安装包：

- Windows x64：.exe installer 或 .zip
- macOS Apple Silicon / Intel：.dmg
- Linux x64：.AppImage 或 Debian / Ubuntu .deb

桌面壳本身的特点：

- **桌面会话工作区**：项目 / 任务导航、会话对话、模型选择、权限模式、会话日志
- **专家预设**：按当前任务启用代码审查 / 架构 / 前端 / 后端 / 运维等不同专业角色
- **技能中心**：在设置中查看、启用、停用、上传和管理本地与共享 Agent 技能
- **归档管理**：搜索已归档会话、按需恢复、或永久清理归档记录
- **IM 助理**：在一个界面中配置钉钉、飞书、Lark、微信、企业微信、QQ、Telegram 等可用频道
- **插件市场**：无需离开桌面客户端即可发现、安装、更新、启用和诊断插件
- **定时自动化**：使用内置 DSH 定时能力，在同一工作台管理周期任务

应用沿用当前用户的 DSH 数据目录（Windows 为 `%USERPROFILE%\.dsh`），升级桌面客户端后，已有会话和配置仍会保留。

## 安全的本地运行时

应用只在经过校验的 **127.0.0.1 loopback** 地址启动 DSH，并把浏览器 UI 承载在桌面壳中。外部 HTTP(S) 链接在系统浏览器打开；File / JavaScript / data URLs 全部 block。

Electron 使用 context isolation + sandboxing，Node.js integration 在 DSH 页面 disabled。

这是和 simedw egress proxy 哲学的反面对照：

- **simedw 的 egress proxy** 把 agent 关在 iptables + mitmproxy 后，让 agent 看见完整网络行为（debug 视角）
- **coolyujiyu 的 127.0.0.1 loopback** 把 DSH 锁在 loopback，让用户看见 UI 但不暴露网络层（user 视角）

两个 solo engineer 都在做「sandbox 在边界替你看」，但一边是给 agent 看网络层，一边是给 user 看 UI。视角不同，哲学一致。

## 6 个 feature products

DSH Codex Desktop 不只是一个 wrapper——它把 6 个 feature products 打包成一个产品：

| Feature product | 角色 |
| --- | --- |
| `@michengai/dsh-codex-ui` | Codex 风格工作台 UI |
| `@michengai/dsh-agency-agents` | 专家预设管理 |
| `@michengai/dsh-skills-manager` | 技能管理 |
| `@michengai/dsh-archive-manager` | 归档管理 |
| `@michengai/dsh-im-connect` | IM 助理 |
| `@michengai/dsh-automation` | 定时自动化 |

每个 feature product 可以独立安装；所有 6 个 bundled with 桌面应用。仓库提供 `dshmarket` 作为插件市场入口，让社区贡献 feature。

这又是 solo engineer 的 cross-pattern：**先做 wrapper 聚合多个 sub-product，再发布一个端到端桌面应用**。OpenAI Codex app 是这种模式（Codex UI + Codex runtime + Codex skills），coolyujiyu 的 DSH Codex Desktop 是「Codex 模式应用到 DeepSeek Harness」。V7 Blog 把 simedw 个人哲学包装成 V7 内部流程，是「公司包装个人」的另一面。
