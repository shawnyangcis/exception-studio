团队有 status page。

statuspage.io、incident.io、自建 status page。所有 service 状态：operational / degraded / partial outage / major outage / maintenance。订阅通知：邮件 / SMS / Slack / RSS。公开 incident log：每次事故从开始到结束的时间线。

订阅者在订阅列表里，每次状态变化收到通知。

solo engineer 没有 status page。

我自己就是 status page。

我的站点挂了，我自己发推。我恢复了一篇新文章。我没挂，访问者自己看就行。公开的 incident log 是我的 commit history——`git log` 显示每次恢复时间。

我没订阅通知系统的必要——访问量 1000 的站点，订阅者 0。我没 incident log 的必要——commit history 就是 log。我没 RSS 的必要——访问者直接刷新页面。

团队 status page 的价值是「让用户知道系统状态」。前提是用户量大、需要主动告知、需要信任建设。solo engineer 没这个问题——我的访问者直接看我的推或者直接刷新。

一人工程的 status page = 我发推。不是 statuspage.io。
