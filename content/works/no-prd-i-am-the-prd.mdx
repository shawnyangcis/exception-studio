团队有 PRD。

Product Requirement Document：每次新 feature 一份 50 页 PRD。Spec：技术规格说明。Acceptance criteria：什么算完成。RFC：技术方案评审。Wireframe：UI 设计稿。User research：用户访谈、问卷、数据分析。

PRD 模板：背景 / 目标 / 非目标 / user stories / 成功指标 / 风险 / 替代方案。写 2 周，评审 1 周，批准 1 周。

solo engineer 没有 PRD。

我自己就是 PRD。

我想做什么就做什么、为什么做就为什么做、做到什么程度就什么程度。没人评审我、没人批准我、没人 user stories 描述给我。

我没 PRD 模板的必要——我自己知道背景、目标、user stories。我没 spec 的必要——commit message 描述清楚就行。我没 acceptance criteria 的必要——我自己验收。我没 RFC 的必要——架构我定。我没 wireframe 的必要——UI 我自己画。我没 user research 的必要——访问者自己看散文。

团队的 PRD 价值是「多人协作时对齐目标」。前提是成员多、需要评审、需要 stakeholder 同意。solo engineer 没这个问题——我的目标我自己定、我自己执行、决定延迟 = 0。

一人工程的 PRD = `git log`。不是 50 页 PRD。
