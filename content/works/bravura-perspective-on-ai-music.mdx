HN show 上 simedw 帖子（HN 2026-08-20）评论者 bravura 写了一句话评论。

那句话是 solo engineer 视角的对外延伸。

## HN show 评审者关注什么

HN show 评论者通常关注：

- 技术可行性（125M 模型 + iPhone Core ML 真能跑吗）
- 评测方法（Gemini pairwise 70% 一致真的可靠吗）
- 商业化路径（App Store 11 天过审，月收入多少）
- 用户体验（端侧 + 0 上传 + 0 月费，用户怎么评价）

4 个关注点是 solo engineer 的真实挑战。

## 一人工程的对外姿态

solo engineer 面对社区评审者：

- 公开失败清单（8 个失败 commit）
- 公开训练参数（DPO β=0.03 + 125M 模型 + 4 × RTX 4090）
- 公开评测方法（Gemini pairwise + 自己听 + 一致率）
- 公开商业结果（App Store 11 天 + 月收入不公开）

4 个公开 = 一人工程的对外姿态。

## HN show 评审 vs 学术评审

HN show 评审者 = 工程师 + 投资人 + 独立开发者 + 业余爱好者。混合群体。

学术评审者 = 教授 + 博士生 + 研究员。专业群体。

simedw 选 HN show 评审（公开 GitHub + README + HN 帖），不选学术评审（不发论文 + 不写 related work）。

HN show 评审 = 工程师视角（125M 真能跑吗？→ 能，因为量化）。
学术评审 = 研究视角（DPO β=0.03 为什么是最优？→ 不知道，因为没扫）。

solo engineer 选工程师视角。

## bravura 的可能视角

bravura 可能是独立开发者 / 投资人 / 工程师。HN show bravura 通常关注实用主义：

- 这项目能 ship 吗？→ 能，App Store 已上线
- 这项目能赚钱吗？→ 不公开
- 这项目能教人吗？→ 能，README + 14 个 commit 是教程
- 这项目能继续吗？→ 能，simedw bullet 3 步 + HN 评论反馈

4 个能 = bravura 视角下的一人工程可行性。

## 一人工程的对外姿态边界

solo engineer 面对社区的姿态：

- 公开失败（README 失败清单）
- 公开训练参数（README 模型细节）
- 公开评测方法（README 评测章节）
- 公开商业化结果（App Store 公开链接）

不公开：

- 月收入（隐私）
- 用户数据（隐私）
- 内部实验笔记（隐私）
- 失败的情绪（诚实但不必公开）

4 公开 + 4 不公开 = 一人工程的对外姿态边界。

## 洞穴人格式补充

洞穴人格式第七篇 readme 写过 solo engineer 的 README = 公开 + 不公开的边界。

bravura 等 HN 评审者 = 读 README 的人。README 写得清楚，评审者给好评；写得不清楚，评审者跳过。

一人工程的对外姿态 = README 写得好不好。

## 一人工程的社区哲学

solo engineer 不在学术圈混（不发论文 + 不写 related work），solo engineer 在 HN show 圈混（公开 README + HN 帖 + App Store）。

HN show 圈是 solo engineer 的学术圈。

solo engineer 公开失败清单 → HN show 评审者读 → HN 评论反馈 → simedw bullet 3 步。这是 solo engineer 的 cycle。
